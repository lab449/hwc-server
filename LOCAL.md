# Локальный запуск

Нужен работающий Docker Desktop. Каталог `server_task_data/` должен содержать задания и `tasks_info.json`; в Git он не хранится.

```sh
docker compose -f compose.local.yaml up -d --build
```

Страница: http://localhost:8080/ . API проверки доступности: http://localhost:8080/api/ok . MongoDB доступна только локально на порту 27018; данные хранятся в отдельном томе `hwc-local_mongodb-local`. Исходный дамп `mongo-seed/` автоматически не загружается.

Проверка и остановка:

```sh
docker compose -f compose.local.yaml ps
docker compose -f compose.local.yaml logs --tail=50 hwc
docker compose -f compose.local.yaml stop
```

После изменения Python-кода пересоберите приложение командой запуска. Изменения в `server_task_data/` видны через подключённый каталог. Для пересчёта конфигурации заданий перезапустите `hwc`:

```sh
docker compose -f compose.local.yaml restart hwc
```

## Проверки API

После пересборки приложения:

```sh
docker compose -f compose.local.yaml exec -T hwc python3 -m unittest discover -s tests -p 'test_*.py' -v
docker compose -f compose.local.yaml exec -T hwc python3 - < tests/api_e2e.py
```

E2E запускает отдельный HTTP-процесс с базой `hwc_e2e_<случайный идентификатор>` и удаляет только эту базу после завершения. Рабочая база локального приложения не используется. Для проверки всех шести работ они должны быть включены в локальном `tasks_info.json`. Проверяются выдача и оценка нулевого варианта, регистрация и вход, ошибочные запросы, конкурентная выдача варианта и лимит попыток.

ID студента — положительное целое число в пределах BSON int64 (до 9223372036854775807); ограничения по году поступления нет. Новые пароли сохраняются как хеши, вход в существующие учётные записи поддерживается без изменения их записей.

В `StudentsAttempts.submitted_at` для новых сохранённых попыток записывается время получения запроса сервером в UTC (BSON Date с точностью до миллисекунды), до проверки учётных данных и оценки ответа. Время из запроса клиента не используется. Старые записи без этого поля остаются доступными.

Ограничений по частоте запросов или общему IP в приложении нет. Лимит 40 попыток относится к отдельному студенту и лабораторной. E2E дополнительно проверяет 30 студентов, которые регистрируются, получают задания и отправляют ответы с одного IP. При настройке внешнего прокси следует учитывать общий адрес Wi-Fi аудитории и избегать жёстких лимитов на IP.

Для проверки с той же моделью процессов, что на VPS:

```sh
docker compose -f compose.local.yaml exec -T -e HWC_E2E_SERVER=uwsgi hwc python3 tests/api_e2e.py
docker compose -f compose.local.yaml exec -T hwc python3 tests/classroom_load.py
```

Оба режима используют отдельную удаляемую базу. В uWSGI меняется только адрес тестового сокета; конфигурация workers/threads берётся из `hwc_server.ini`. Нагрузочная проверка проводит 30 студентов одновременно через регистрацию, вход, получение и отправку работы, измеряя задержки каждого этапа.

Лимит попыток обеспечивает уникальный частичный MongoDB-индекс `student_lab_attempt_slot`. Исторические записи не меняются: они уменьшают число доступных слотов новых попыток. Новая запись атомарно занимает свободный слот, ошибка вставки не расходует попытку; отдельного счётчика и миграции старых оценок нет.

Поддерживаемый MATLAB-клиент хранится в `matlab/` и копируется в образ при сборке; старт контейнера не выполняет `git pull`. Студентам доступен `/clients/hwc-matlab-client.zip`, а version API соответствует точным файлам из этого пакета. Обычные числовые HDU ID прежней длины передаются в прежнем формате, без старого диапазона по году; расширение до строкового int64-протокола не требуется. HTTP разрешён всем клиентам и используется по умолчанию в `hwc_connect()`; HTTPS доступен при явном HTTPS URL с проверкой сертификата. Выбранный протокол используется во всех запросах клиента, таймаут — 30 секунд. Production nginx-конфигурация обоих протоколов — `deploy/nginx-hwc-server.conf` (пути Certbot для действующего домена). Нативные MATLAB-проверки и происхождение исходников описаны в `matlab/README.md`.
